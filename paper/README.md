# 本地前向模拟盘

冻结原Alpha158/LightGBM模型，使用实际收盘后固定的订单计划，在下一交易日行情产生后模拟结算。不会调用券商或真实交易接口。

## 每日查看什么

打开账户目录中的`dashboard.html`。默认突出显示下一交易日的模拟买入清单：股票名称、代码、按信号收盘价估算的整手股数、参考价与金额。可切换卖出、当前持仓和本次成交，选择历史日期，导出最新买卖CSV。股数是估算，不能当作已成交确认；实际模拟成交受次日价格、费用、容量、整手和现金约束。

首日只有收盘后计划，净值为1、没有成交；下一交易日结算后才有持仓和收益。历史演练使用不同账本并显式标记，不能混入正式账户业绩。

## 保持一致的规则

- 原冻结模型、约Top50、每日通常最多替换5只，计划只用前收盘分数与已知持仓、现金和价格。
- 原买入5bp、卖出15bp费用、每笔最低5元，另以实际执行价格加入每边3bp不利滑点；不重复扣滑点费。
- 使用原Qlib Exchange的容量、价格可行性、整手、现金及方向限制。日线模拟不重放真实竞价盘口。
- 用SQLite保存每个信号日唯一记录；订单附唯一标识。相同日期重复运行不会再次成交或追加账户行。
- 跨数据快照以共同历史日factor对齐复权单位，并核对历史价格与factor比例；不一致时停止。账户仍属于复权单位口径，不等同完整实盘现金股份账簿。
- 原模型、配置和交易代码的指纹固定；漂移、过期数据、缺失单位基准等异常会阻止继续记账。
- 已固定的订单若离线错过结算，按原目标日行情补记，并记录实际记账日；中间未产生的信号不会事后生成订单。

## 运行

依赖仓库的`requirements.txt`；运行时使用已安装的相同Python环境。账户目录必须独立于研究回测。

```bash
python paper/cli.py --feed /path/to/verified_qlib_feed --account /path/to/paper_account
python paper/dashboard.py --account /path/to/paper_account --names /path/to/names.json
python -m unittest discover -s paper -p 'test_*.py'
```

`--historical-rehearsal --asof YYYY-MM-DD`只用于独立演练账本。正式账户要求上海时间16点后、行情等于当日，且feed存在已完成验证的`verified.json`。

每日入口为`paper/daily.py --home /path/to/paper_home`。paper_home包含`app/`冻结程序、`feeds/current.json`指向已验证缓存、`account/`、`logs/`、`names.json`和`status.json`。当前机器部署于`D:\Codex\csi300-paper`。`app/paper/update_feed.py`负责同源公开快照更新，`CSI300_FEED_DIR`指定数据目录；初次部署须以已验证Qlib缓存初始化。数据更新脚本位于同一paper目录。

行情来自chenditc/investment_data每日公开发布，校验发布方完整压缩包SHA256与字节数，仅保留近期必要字段、历史沪深300成员及官方缓存交易日历。复权价格、factor、复权百股成交量、千元成交额沿用研究数据口径。首次接入版本为2026-10-30，源快照比对信息随feed保存。股票名称来自腾讯公开行情的名称字段，只用于展示，不用于模型输入。

## 运行与评价边界

自动化运行依赖电脑在线、网络及Codex本地任务可用。默认收盘后检查，若数据尚未发布则暂停，后续检查补试；同一日期只记一次。

目前尚未接入持续更新的H00300全收益基准，因此界面显示实际本地模拟账户净值、买卖计划和成交，不计算或宣称模拟盘超额IR。历史回测IR不会作为模拟盘业绩展示。今后接入基准时须匹配实际首次投入时点。

SQLite账本为事实来源；CSV和看板是可重建的展示文件。遇到`blocked`先查`status.json`和相应日志，勿删除账本、手动改持仓或把历史演练覆盖到正式账户。
